# 黄氏家族谱网站

一个静态网页，点击姓名可以展开下一代。电脑和手机都可以看。名单放在一份 Google 表格里，网站会自动从表格更新。

**网站地址：<https://yisiangeng.github.io/huang_family_zupu/>**

## 给看网站的人
- 点一个姓名，展开他的儿子；再点一次收起。名牌右上角的小数字是他有几个儿子。
- 同一代最多同时展开 3 个人的分支（手机 2 个）。再展开新的，最早展开的会自动收起。
- 右上角的 **−、+、适应** 可以缩放。想看整棵树，点 **适应**；点 **100%** 恢复原大小。
- 右下角的「添加新成员」是给受邀的编辑者用的，会在新窗口打开 Google 表格。

## 给填表的人：怎样添加新成员

### 你需要什么
- 管理员已经邀请你为表格的**编辑者**。没有邀请的话，打开表格会看到「需要权限」的页面，请联系管理员。
- 一个浏览器就够了，手机或电脑都可以。

### 表格里有三个工作表（页面最下方的标签）
| 工作表 | 用途 | 你能改吗 |
|---|---|---|
| **族谱** | 完整名单，每人一行：编号、姓名、父亲编号 | 不能，已锁定，只有管理员能改 |
| **新加入成员** | 你在这里添加新成员 | **能，只改这一页** |
| **说明** | 简短的使用说明 | 不能 |

### 添加一个新成员（三步）
1. **找到他父亲的编号。** 到「族谱」工作表，找到他父亲那一行，记下最左边的**编号**。可以用 Ctrl+F（手机用「查找」）搜他父亲的名字。
   - 同名的人没关系，网站靠编号分辨。注意核对父亲姓名，找对人。
2. **到「新加入成员」工作表，在第一个空行填两格：**
   - **A 列 姓名**：新成员的名字，不要有空格或逗号。
   - **B 列 父亲编号**：第 1 步记下的数字。
3. **看 C 列。** 它会自动显示这个父亲编号对应的姓名。请确认是你要的人。如果显示「找不到」，说明编号填错了，改一下就行。

填完就可以离开，不用按保存（Google 表格会自动保存）。**这一行不会马上变化**：脚本每天凌晨自动处理一次，到时候这一行会**消失**，因为它已经被移到「族谱」工作表的最后，并得到了一个新的编号。第二天可以去「族谱」最后几行确认。

- 请填在第一个空行，不要覆盖别人还没处理的行（它们还在表里，说明还没轮到处理）。
- 处理之前，你随时可以自己修改或删除这一行。

> 例子：给「则炀」（编号 4）新增一个儿子「明德」。在「新加入成员」填：A = 明德，B = 4。第二天，「族谱」最后会多出一行：编号 80（以实际为准）、明德、父亲编号 4。

### 处理后这一行还在？
如果第二天这一行还在，D 列（处理结果）会写着原因。改好后，下一次处理时会再检查：

| D 列的提示 | 意思 | 怎么办 |
|---|---|---|
| 找不到父亲编号 … | 这个编号在「族谱」里不存在 | 回「族谱」核对编号 |
| 父亲编号必须是数字 | B 列填了名字或别的字 | 只填数字 |
| 姓名不能含空格、逗号或特殊符号 | 姓名里有空格或逗号 | 删掉它们 |
| 这位父亲名下已经有同名的儿子「…」 | 同一位父亲下已经有同名的人，多半是重复填了 | 先到「族谱」确认；如果真是另一个人，在姓名后加一个区分的字 |

如果只填了姓名或只填了父亲编号，这一行会先留着，等你填完另一格才处理。

### 兄弟的顺序
网站按编号从小到大排兄弟，编号小的在左边（年长）。新添加的成员编号最大，所以会排在兄弟的最后。如果顺序要调整，请联系管理员。

### 多久出现在网站上
表格要等当天凌晨的处理，**网站每月 1 号才会自动更新一次**，所以新成员不会马上出现。想早点看到，请管理员先在表格菜单点「族谱工具 → 处理新加入成员」，再手动更新网站（一分钟的事，见下方「手动更新与本地运行」）。

### 你不能做的事
- 修改或删除已有的人（改错字、改父亲、删除）：请联系管理员。
- 修改「族谱」和「说明」工作表：已被锁定。

## 给管理员和开发者：系统怎么运作

### 整体流程
```
填表的人在「新加入成员」添加一行         （Google 表格）
  → Apps Script 每天凌晨运行一次：检查，通过就分配编号并移到「族谱」，清空这一行   （表格里）
  → 「族谱」工作表被「发布到网络」成一个公开的 CSV 链接
  → GitHub Actions（每月 1 号，或手动）下载这个 CSV           （sheet_url.txt 里的链接）
  → build_data.py 检查数据，重新生成 data.js，并提交
  → GitHub Pages 重新发布网站                                （一两分钟）
  → 浏览器里的 app.js 读取 data.js，画出族谱树
```
网站本身不会连到 Google。它只读 `data.js`，所以表格临时出问题也不会影响网站。

### 文件
| 文件 | 用途 | 需要改吗 |
|---|---|---|
| `index.html` | 网页结构、标题、右下角「添加新成员」链接（这里写着 Google 表格的编辑链接） | 改标题或表格链接时 |
| `style.css` | 外观（颜色、字体、大小） | 一般不用 |
| `app.js` | 画树、展开/收起、缩放 | 一般不用 |
| `data.js` | 网站读取的名单，**自动生成** | 不要手动改，会被覆盖 |
| `sheet_url.txt` | 存放 Google 表格发布出来的 CSV 链接 | 设置一次即可 |
| `build_data.py` | 读取表格、检查数据、生成 `data.js` | 一般不用 |
| `.github/workflows/build-data.yml` | 定时任务：运行 `build_data.py` 并提交结果 | 一般不用 |
| `google_sheet/Code.gs` | 贴在 Google 表格里的脚本（移动新成员） | 设置一次即可 |
| `google_sheet/说明.txt` | 表格里「说明」工作表的文字 | 改说明时两边一起改 |
| `族谱备份.xlsx` | 「族谱」表的只读备份，每次名单有变化时自动更新 | 不要改，会被覆盖 |

### 第一步：表格里的脚本（`google_sheet/Code.gs`）
- **触发**：每天运行一次（`setup()` 建立了这个定时触发器，时间由脚本里的 `RUN_HOUR` 决定，默认凌晨 3 点；Google 会在这一小时内的某个时间运行）。拥有者也可以随时用表格菜单 **族谱工具 → 处理新加入成员** 手动运行。运行时会加锁，不会同时处理两次。
- **为什么不是填完马上处理**：填表的人可以在处理之前自己修改或删除，也不会看到「族谱」被马上改动。代价是出错提示（D 列）要等到下一次处理才会出现，所以 C 列的父亲姓名核对很重要。
- **逻辑**：
  1. 读出「新加入成员」的每一行（A 姓名、B 父亲编号），读出「族谱」现有的所有编号。
  2. 跳过空行和只填了一半的行。
  3. 检查：姓名没有空格、逗号和特殊符号；父亲编号是数字且存在；这位父亲名下没有同名的儿子。不通过的，把原因写在 D 列，行留在原处。
  4. 通过的：新编号 = 目前最大编号 + 1，按从上到下的顺序依次分配，写到「族谱」A 到 C 列的最后；然后清空这一行的 A、B、D 列（不删除行，这样 C 列的公式不会丢）。
- **权限**：脚本以安装它的人（拥有者）的身份运行，所以「族谱」工作表虽然被锁定，脚本仍然可以写入。
- 脚本只写 A 到 C 列。「族谱」的 D、E 列（父亲姓名、第几代）是预先填到第 500 行的公式；超过 500 行时，把公式往下拖即可。

### 第二步：发布与下载
- 「族谱」工作表通过 **文件 → 分享 → 发布到网络** 发布成 CSV。这个链接不需要登录就能读取，只包含这一个工作表。
- 链接写在 `sheet_url.txt`（`#` 开头的行是注释）。链接是公开的，但网站上的名字本来就是公开的；所以不要把私密资料写进「族谱」工作表（包括 F 列「备注」）。

### 第三步：GitHub Actions（`.github/workflows/build-data.yml`）
- **什么时候运行**：
  - 每月 1 号 02:00 UTC（UTC+8 时区是早上 10:00）
  - 手动：仓库的 **Actions → 更新族谱 → Run workflow**
  - 推送了 `sheet_url.txt` 的修改时
- **做什么**：
  1. 运行 `python build_data.py`，读取 `sheet_url.txt` 里的链接。
  2. 如果数据有变化，提交新的 `data.js` 和 `族谱备份.xlsx`（后者是「族谱」表的只读备份）；提交者是 `github-actions[bot]`。
  3. 每次还会更新一个小文件 `.last_sync`（日期）。这是为了让仓库保持「有活动」：GitHub 在仓库 60 天没有任何提交时，会停用定时任务。
- **需要的权限**：仓库 **Settings → Actions → General → Workflow permissions** 选「Read and write permissions」，否则机器人提交不了。

### `build_data.py` 的检查
读取 CSV 的 A 到 C 列（第 1 行是标题），只要有一项不通过，就**不更新** `data.js`，并在 Actions 里把所有问题列出来（任务显示红色 ✗，GitHub 也会发邮件通知）：
- 编号必须是数字，不能重复，不能缺姓名；
- 姓名不能含空格、逗号、反引号和特殊符号；
- 父亲编号必须存在，不能是自己，也不能形成循环；
- 必须有且只有一位始祖（父亲编号为空）；
- 下载到的不是 CSV（例如没有发布到网络）时，会提示检查发布设置。

数据通过检查后，生成 `data.js`：每人一行，用 Tab 隔开「编号 姓名 父亲编号」。

### 网站怎么读 `data.js`
- `app.js` 把名单变成一棵树。**编号小的是兄长**，兄弟按编号排序。
- 点击姓名时才画出下一代，收起时移除。每一代最多同时展开的人数在 `app.js` 最上面设置：`MAX_OPEN_PER_GENERATION = 3`、`MAX_OPEN_PER_GENERATION_PHONE = 2`。
- 顶部的「N代 · M人」由数据自动算出。
- 缩放用的是 CSS `zoom`，需要较新的浏览器（Chrome、Edge、Safari，Firefox 126 以上）。

### 手动更新与本地运行
- **手动更新网站**：GitHub → **Actions** → 左边点 **更新族谱** → 右边 **Run workflow** → 绿色 **Run workflow**。刷新页面，出现绿色 ✓ 后，等一两分钟网站更新。
- **本地生成**：`python build_data.py`（需要先 `pip install openpyxl`，用来写备份；Windows 上用 `python -X utf8 build_data.py`）。可以加参数指定来源：`python build_data.py "CSV链接"` 或 `python build_data.py 文件.csv`。
- **本地预览**：双击 `index.html`。

### 出问题了怎么办
| 现象 | 可能的原因 | 怎么办 |
|---|---|---|
| Actions 显示红色 ✗ | 表格数据有错误 | 点开这次运行，看列出的问题（会写明第几行），修正表格，再点一次 Run workflow |
| 提示「下载到的不是 CSV」 | 表格没有发布，或发布后又取消了 | 重新 文件 → 分享 → 发布到网络，选「族谱」和 CSV，把新链接放进 `sheet_url.txt` |
| 红色 ✗，原因是无法推送（permission denied） | 机器人没有写入权限 | 见上面「需要的权限」 |
| 新成员一直不从「新加入成员」消失 | 还没到每天的处理时间；脚本没有安装，或授权过期 | 先点菜单「族谱工具 → 处理新加入成员」试一下；没反应就在 Apps Script 里重新运行一次 `setup()` 并授权（会把旧的触发器换掉）；D 列有提示的话，先按提示修改 |
| 表格里已更新，网站没变 | 还没到每月更新；或浏览器缓存了旧页面 | 手动 Run workflow；刷新网页（Ctrl+F5，手机可以用无痕窗口打开） |
| 定时任务不再自动运行 | 仓库超过 60 天没有任何提交，被 GitHub 停用 | 在 Actions 页面重新启用，并手动 Run workflow 一次 |
| 要修改或删除已有的人 | 只有拥有者能改「族谱」 | 在「族谱」里直接改。注意：编号不能重复，父亲编号要存在，有且只有一位始祖 |

### 上传到 GitHub Pages
1. 在 GitHub 新建一个仓库（Repository）。
2. 点 **Add file → Upload files**，把所有文件（含 `.github` 文件夹）拖进去，按 **Commit changes**。
3. 进入 **Settings → Pages**，Source 选 **Deploy from a branch**，Branch 选 `main`、文件夹 `/ (root)`，按 **Save**。
4. 等一两分钟，网址会是：`https://你的用户名.github.io/仓库名/`（本站：<https://yisiangeng.github.io/huang_family_zupu/>）

注意：GitHub Pages 的网页是公开的，有网址的人都能看到。网页已设置不让搜索引擎收录，但这不等于私密。

## 给管理员和开发者：一次性设置

### Google 表格（只做一次）
1. **建表**：新建一个 Google 表格，建三个工作表：「族谱」「新加入成员」「说明」。名单可以从 `族谱备份.xlsx` 导入：上传到 Google 云端硬盘，用 Google 表格打开，选 **文件 → 另存为 Google 表格**，再补上另外两个工作表。「族谱」A 到 F 列的标题是：编号、姓名、父亲编号、父亲姓名、第几代、备注。D 列和 E 列要用公式（备份里只有结果，没有公式），例如第 2 行：
   - D2：`=IF(OR(B2="",C2=""),"",IFERROR(INDEX($B:$B,MATCH(C2,$A:$A,0)),"找不到父亲编号"))`
   - E2：`=IF(B2="","",IF(C2="",1,IFERROR(INDEX($E:$E,MATCH(C2,$A:$A,0))+1,"")))`
   - 往下拖到第 500 行左右。
2. **「新加入成员」的格式**：标题是 A1 `姓名`、B1 `父亲编号`、C1 `父亲姓名（核对用）`、D1 `处理结果`。C2 填 `=IF(B2="","",IFERROR(INDEX(族谱!$B:$B,MATCH(B2,族谱!$A:$A,0)),"找不到"))`，往下拖到第 300 行（每行一条公式，所以脚本只清空 A、B、D 列，不会删除行）。「说明」工作表的内容用 `google_sheet/说明.txt`。
3. **安装脚本**：在表格里点 **扩展程序 → Apps Script**，删掉原有内容，把 `google_sheet/Code.gs` 整段粘贴进去并保存；选择函数 `setup`，点 **运行**，按提示授权（用拥有者账号，只需一次）。`setup` 会建立每天凌晨运行一次的定时触发器。
4. **锁定工作表**：右键「族谱」和「说明」的标签 → **保护工作表** → 权限设为「仅限我」。脚本以拥有者身份运行，仍然可以往「族谱」添加新成员。
5. **分享**：点右上角 **分享**，把要帮忙填写的人加为**编辑者**，「常规权限」保持**受限**。
6. **发布到网络**：**文件 → 分享 → 发布到网络**，「链接」选 **族谱** 工作表、格式选 **逗号分隔值 (.csv)**，点发布，复制链接。
7. **把链接放进网站**：粘贴到仓库的 `sheet_url.txt`（替换那一行链接），提交。GitHub 会立即运行一次，之后每月自动运行。
8. **测试**：在「新加入成员」加一个测试成员，点菜单 **族谱工具 → 处理新加入成员**（不用等到明天），确认它出现在「族谱」最后；测试后删掉「族谱」里的这一行，并手动 Run workflow 一次，让网站与表格一致。
